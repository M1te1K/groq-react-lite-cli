# CLI-агент с планированием (ReAct-lite)

Выбран вариант 5 (ReAct-lite), чтобы показать цепочку зависимых действий: агент сам выбирает инструменты через Groq, получает официальный курс ЦБ и выполняет расчёты отдельным калькулятором.

Реализованы только вариант 5 и общие требования задания. CLI и Groq — решения проекта; тесты и Dockerfile — включённые бонусы. Telegram, постоянная память и деплой в объём не входят.

## Установка и запуск

Нужны Git, Linux/macOS или WSL с Linux, [uv](https://docs.astral.sh/uv/getting-started/installation/), интернет для установки и API, собственный действующий ключ [GroqCloud](https://console.groq.com/keys). Python 3.12 будет установлен `uv`, если его ещё нет. Общий дедлайн использует POSIX `setitimer`; Windows без WSL не поддерживается. Проверенная версия uv — 0.13.1.

В терминале Linux/macOS или внутри WSL:

```sh
git clone https://github.com/M1te1K/groq-react-lite-cli.git
cd groq-react-lite-cli
uv sync --frozen --no-editable
cp -n .env.example .env
```

Создайте ключ в [GroqCloud](https://console.groq.com/keys) и впишите его после `GROQ_API_KEY=` в `.env` локальным редактором. Ключ обязателен для запросов к модели; CLI-команды доступны и без него. Остальные настройки можно оставить как в шаблоне. Затем:

```sh
uv run --frozen --no-editable react-lite --trace
```

Обычный запуск показывает такие же компактные шаги:

```sh
uv run --frozen --no-editable react-lite
```

`--trace` сохранён для совместимости: он также показывает только короткие действия. Подробные технические события всегда записываются в JSONL-файл и в терминал не выводятся. Уже работающий процесс нужно завершить через `/exit` и запустить заново, чтобы загрузить изменения установленного пакета.

Альтернативы после установки: `.venv/bin/react-lite --trace` и `.venv/bin/python -m react_lite`. Пакет устанавливается обычным wheel; это также обходит проблему скрытых editable `.pth`-файлов на macOS. Для разработки после изменения исходников пересоберите его явно:

```sh
uv sync --frozen --no-editable --reinstall-package react-lite-cli
```

Пример диалога:

```text
Вы: Узнай курс USD на сегодня и посчитай стоимость 500 долларов в рублях
→ Получаю курс USD в ЦБ…
→ Рассчитываю 500 × <полученный курс>…
Бот: 500 USD = <сумма> ₽. Курс ЦБ: <курс> ₽ за 1 USD,
     дата курса: <дата>; источник: Банк России (https://www.cbr.ru/...).
Вы: а для 1000 долларов?
Вы: /reset
Вы: /exit
```

Пример показывает оформление; числа каждый раз берутся из результатов инструментов. Следующее действие выбирает модель. Обычный вопрос может завершиться без инструментов и без строк действий. Получение курса и расчёт могут повторяться, если модель действительно выбрала новый вызов.

Строки действий появляются перед выполнением инструмента, с голубой стрелкой в TTY. Итог печатается обычным цветом один раз. При перенаправлении, `NO_COLOR` (включая пустое значение) или `TERM=dumb` ANSI-коды не используются. Ошибка инструмента или сетевая повторная попытка обозначаются короткой строкой без аргументов, ID и полных результатов.

Команды: `/help` показывает справку, `/reset` удаляет всю историю из памяти, `/exit` завершает работу. Неизвестная команда показывает подсказку. `Ctrl+C` и конец ввода (`Ctrl+D`) корректно завершают приложение, в том числе во время запроса.

## Настройки

Переменные окружения имеют приоритет над `.env` в текущей папке. Значения проверяются при старте.

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `GROQ_API_KEY` | пусто | Обязателен для LLM; при отсутствии доступны CLI-команды, запросы дают «Сервис временно недоступен» |
| `GROQ_MODEL` | `openai/gpt-oss-120b` | Модель; выбранное имя печатается при старте, автоматической замены нет |
| `MAX_STEPS` | `6` | Число итераций цикла, от 1 до 30 |
| `MAX_TOOL_CALLS` | `6` | Общее число разрешённых вызовов инструментов на запрос, от 1 до 50 |
| `REQUEST_TIMEOUT_SECONDS` | `60` | Общий дедлайн одного пользовательского запроса, от 0.1 до 300 секунд |
| `NETWORK_TIMEOUT_SECONDS` | `10` | Таймаут каждой сетевой фазы, ограниченный остатком общего времени, от 0.1 до 60 секунд |
| `NETWORK_ATTEMPTS` | `2` | Всего попыток одного обращения к Groq/ЦБ, включая первую, от 1 до 3 |
| `LOG_FILE` | `logs/agent.jsonl` | Путь к JSON Lines логу относительно текущей папки; можно указать абсолютный |

На 16 октября 2026 года модель перечислена в [официальном списке Groq](https://console.groq.com/docs/models) и поддерживает [local tool calling](https://console.groq.com/docs/tool-use/overview). С локально настроенным ключом проверены реальный сценарий 500 USD, продолжение про 1000 USD и `/reset`; для другого аккаунта доступность нужно проверять отдельно. Модель не заменялась.

## Как работает цикл

Одна **итерация** — одно логическое обращение к модели и исполнение всех разрешённых вызовов из её ответа. Финальный ответ без инструментов тоже занимает итерацию. Сетевые повторы внутри обращения расходуют время и `NETWORK_ATTEMPTS`, но не добавляют итераций. При стандартных настройках демонстрация обычно занимает три итерации: выбор курса, выбор расчёта по наблюдению, итоговый ответ.

1. К системной инструкции с текущей датой `Europe/Moscow` добавляются история и новый запрос.
2. Groq получает описания двух локальных инструментов с `tool_choice="auto"`.
3. Если пришли `tool_calls`, приложение сохраняет сообщение assistant, проверяет имена и аргументы, выполняет инструменты и добавляет сообщения tool с исходными `tool_call_id`.
4. Модель получает результаты и выбирает следующее действие. При ответе без вызовов цикл завершается.

`parallel_tool_calls=False`: зависимые действия должны идти через отдельные наблюдения. Дополнительно есть общий счётчик вызовов: неверные аргументы и неизвестные инструменты тоже расходуют лимит. Если целый пакет не помещается в оставшийся лимит, ни один его вызов не исполняется, каждому ID сопоставляется структурированная ошибка, запрос завершается сообщением о лимите. Поэтому несколько вызовов в одном ответе не обходят ограничение. При достижении `MAX_STEPS` возвращается сообщение о лимите шагов.

Повторяются только сетевые ошибки, HTTP 429 и 5xx, с паузами 0.25/0.5 секунды; 401 не повторяется. [Встроенные повторы SDK](https://github.com/groq/groq-python#retries) отключены (`max_retries=0`). POSIX-таймер прерывает весь запрос, включая ожидание SDK, чтение тела ответа и паузы. Ядро вызывается в главном потоке. Текст ошибки Groq не записывается: технический лог содержит тип исключения и HTTP-статус. Пользователь получает «Сервис временно недоступен», а CLI принимает следующий запрос.

Ошибки инструментов имеют вид `{"ok": false, "error": {"code": "...", "message": "..."}}`. Модель может исправить вызов или сообщить о проблеме. При сбое LLM/общем дедлайне промежуточная часть неуспешного хода отбрасывается из истории, остаются запрос и сообщение об ошибке; журнал сохраняет события. Это исключает незакрытые tool calls в следующем API-запросе.

История хранится только в памяти процесса. `/reset` удаляет все сообщения, включая вызовы и результаты. Уже записанный технический журнал команда не удаляет. Если длинный диалог превысит контекст модели, начните новый через `/reset`.

## Инструменты и точность

`get_exchange_rate(currency, date)` принимает код из трёх заглавных букв и календарную дату `YYYY-MM-DD`. Он обращается только к официальному [XML-сервису Банка России](https://www.cbr.ru/development/SXML/), передаёт `date_req=DD/MM/YYYY`, читает XML с учётом его кодировки, запятой и номинала. Курс за единицу равен `Value / Nominal`; возвращаются `requested_date`, `effective_date`, `nominal`, `value_rub`, `rate_rub_per_unit`, источник и ссылка запроса. Фактическая дата может быть раньше запрошенной. Неизвестный код, плохой XML, слишком большой ответ и недоступность сервиса возвращают ошибки; запасной источник не используется.

`calculate(operation, a, b)` поддерживает `add`, `subtract`, `multiply`, `divide`. Операнды — строки с точкой, до 30 целых и 20 дробных цифр, без экспоненты. JSON-числа не принимаются, чтобы не проходить через `float`. Используется только `Decimal`, без `eval` или исполнения кода. Сложение, вычитание и умножение в этом диапазоне точные; деление округляется в контексте 110 значащих цифр (`ROUND_HALF_EVEN`). Инструмент не округляет результат: исходное значение остаётся в журнале.

Приложение оформляет однозначный валютный ответ по успешным наблюдениям: один курс либо одно умножение по известному курсу, когда в ответе модели указана соответствующая валюта. Сумма показывается до копеек через `Decimal` (`ROUND_HALF_EVEN`), курс — без лишних конечных нулей, дата и ссылка берутся из ЦБ. Это устраняет повторы внутри валютного текста модели. В обычных вопросах, ошибках и составных задачах сохраняется ответ модели с инструкцией отвечать кратко и без служебных названий. Выбор инструментов от этого форматирования не зависит.

## Логи и структура

`logging` пишет JSONL с UTC-временем, `user_id=local`, случайным `request_id`, запросом пользователя, ответом, номерами итераций, ID вызовов, аргументами, результатами, ошибками и повторами. Записи шагов содержат `Thought / Action / Observation`; `Thought` — короткое описание цели, формируемое приложением. Поле reasoning из Groq не сохраняется. При оформлении валютного ответа исходный текст модели и оформленный ответ сохраняются отдельным событием. В терминале остаются только компактные действия и один итоговый ответ. Лог ротируется после 5 MB, хранятся три резервные копии.

Значение настроенного ключа и строки вида `gsk_...` маскируются в логах/trace. `.env`, `.venv` и журналы исключены из Git и Docker-контекста. Запросы и ответы содержатся в журнале, поэтому храните его локально.

```text
src/react_lite/
  agent.py    # Цикл, история, лимиты, системная инструкция
  answers.py  # Оформление однозначных валютных результатов
  console.py  # Короткие действия, TTY-цвет и NO_COLOR
  llm.py      # Синхронный Groq SDK, формат сообщений, повторы
  tools.py    # Схемы Pydantic, Decimal, httpx и XML ЦБ
  budget.py   # Монотонный дедлайн и POSIX-таймер
  events.py   # JSONL, маскирование ключей, выбор компактных событий
  config.py   # pydantic-settings
  cli.py      # Команды и интерактивный ввод
tests/        # Внешние сервисы заменены контролируемыми ответами
```

## Проверки

```sh
uv sync --frozen --no-editable
uv run --frozen --no-editable pytest
uv run --frozen --no-editable ruff check .
```

Тесты не используют сеть или настоящий ключ. Они проверяют арифметику и её ошибки, номинал и даты ЦБ, зависимые вызовы, ошибки SDK, повторы и дедлайн, историю, `/reset` и остальные команды. Для проверяемого результата установки используйте чистую папку и эти же команды.

Проверка с действующим ключом: запустите `--trace`, отправьте демонстрационный запрос, затем «а для 1000 долларов?», `/reset` и новый вопрос. Убедитесь, что видны отдельные получение курса и расчёт с его значением, а ответ содержит сумму, курс, дату и источник. Тесты с подменёнными сервисами не подтверждают эту интеграцию.

Результаты поставки и границы проверок записаны в [docs/verification.md](docs/verification.md). GitHub Actions повторяет установку из `uv.lock`, pytest и ruff на Python 3.12 в Linux и macOS без настоящих ключей. CI — улучшение поставки, не обязательное требование исходного задания.

## Частые проблемы

| Симптом | Что проверить |
| --- | --- |
| `uv: command not found` | Установите uv по [официальной инструкции](https://docs.astral.sh/uv/getting-started/installation/), откройте новый терминал и проверьте `uv --version`. В WSL устанавливайте uv внутри Linux. |
| «Ключ Groq не настроен» | Запускайте из папки с `.env`, заполните `GROQ_API_KEY`. Переменная в окружении имеет приоритет над файлом, даже если она пустая. |
| «Сервис временно недоступен», в логе `AuthenticationError` / 401 | Проверьте ключ локально в GroqCloud и `.env`, затем перезапустите CLI. Текст ключа в журнал не нужен. |
| Модель недоступна, 400/403/404 | Сверьте `GROQ_MODEL` с [моделями Groq](https://console.groq.com/docs/models), доступными вашему аккаунту и поддерживающими local tool calling; измените настройку и перезапустите CLI. Автоматической замены модели нет. |
| HTTP 429 в журнале | Достигнут лимит Groq или ЦБ. После ограниченных повторов запрос завершится сообщением; подождите и отправьте его снова. |
| Не удалось получить курс ЦБ | Проверьте сеть и доступ к `www.cbr.ru`. Другого источника нет, курс после ошибки не подставляется. Для неизвестной валюты проверьте трёхбуквенный код. |
| Лимит шагов, инструментов или времени | Упростите запрос, при длинном диалоге выполните `/reset`. При необходимости измените соответствующий лимит в пределах таблицы выше и перезапустите CLI. |
| Не удалось открыть лог | Укажите доступный для записи `LOG_FILE` и проверьте права на родительскую папку. |
| После правок запускается прежний код | Пересоберите wheel командой `uv sync --frozen --no-editable --reinstall-package react-lite-cli` и запустите новый процесс. |

## Docker (бонус)

```sh
docker build -t react-lite .
docker run --rm -it --env-file .env react-lite --trace
```

Контейнер работает от непривилегированного пользователя; ключ передаётся при запуске. Для ввода нужен `-it`. Журнал по умолчанию находится внутри контейнера и удалится вместе с ним. На машине разработки Docker-клиент есть, но движок недоступен; сборка и запуск контейнера пока не проверены.

## К сдаче

Первоначальная разработка и проверки заняли около 20 минут по оценке отчёта разработки; последующие ревью, правки интерфейса и подготовка публикации в эту оценку не входят. Основная сложность — сохранить корректную последовательность tool calls при ошибках и одновременно ограничить синхронные сетевые запросы общим дедлайном. Следующее улучшение — запуск реальных сценариев Groq как отдельного набора интеграционных проверок, включаемого явно.
